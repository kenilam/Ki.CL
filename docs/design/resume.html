Resume on ki-cl.com

One content source, one view, two outputs: the page and its PDF. See resume.md for the trade-offs.

The page (① to ⑤)

  • • A route in the host, at /resume and /resume/:version
  • • Needs the host, the design remote and an API session
  • • Makes no request for its own data
  • • As available as the least of the three

The file (⑥)

  • • One name for good, revalidated on every request
  • • In the static bucket, streamed by the API, no session
  • • Not in git or the host image
  • • Hidden by the page when its fingerprint is stale

The export (⑦, ⑧)

  • • One renderer: the PDF is the page, printed
  • • Chrome over the DevTools protocol, no dependency
  • • Refuses a third page or the fallback typeface
  • • The phone number comes from .env and stays local
